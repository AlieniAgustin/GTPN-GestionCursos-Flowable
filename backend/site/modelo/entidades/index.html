    Entidades y Persistencia¶

    El modelo de datos relacional del backend se persiste en PostgreSQL mediante Spring Data JPA. Gestiona los registros transaccionales y de negocio permanentes, garantizando trazabilidad histórica e independencia del ciclo de vida de los procesos en Flowable.

    Diagrama Entidad-Relación¶

    erDiagram
    COMPANY ||--o| COMPANY_ACCESS : "posee (1:1)"
    COMPANY ||--o{ COURSE : "solicita (1:N)"
    COURSE ||--o{ PROPOSAL_DOCUMENT : "historial de versiones (1:N)"

    COMPANY {
        bigint id PK
        varchar name "Razón social"
        varchar email "Email de contacto"
        varchar phone "Teléfono"
    }

    COMPANY_ACCESS {
        bigint id PK
        bigint company_id FK, UK
        varchar username UK
        varchar password_hash "BCrypt"
    }

    COURSE {
        bigint id PK
        varchar process_instance_id "ID de Flowable"
        varchar name "Nombre del curso"
        text description
        varchar status "Estado terminal (opcional)"
        bigint company_id FK
        date start_date
        date end_date
    }

    PROPOSAL_DOCUMENT {
        bigint id PK
        bigint course_id FK
        int version "Versión secuencial (1, 2, ...)"
        numeric budget "Presupuesto"
        bytea pdf_blob "Documento PDF generado"
        timestamp created_at
    }

    Descripción de Entidades¶

    1. Course¶

    Representa el expediente central de una capacitación. - processInstanceId: Identificador unívoco de la instancia de proceso en Flowable que orquesta su ciclo de vida. - status (CourseStatus): Almacena el resultado final cuando el curso concluye o se cierra tempranamente (NO_VIABLE, RECHAZADO, SIN_RESPUESTA, FINALIZADO, CANCELADO). - possibleDates: Lista de fechas sugeridas inicialmente por la empresa (almacenadas como JSON en la base de datos).

    2. Company y CompanyAccess¶

    • Company: Datos de contacto y razón social de la empresa cliente.
    • CompanyAccess: Credenciales de acceso al portal de clientes generadas automáticamente durante la etapa de evaluación (§4.1.2). La contraseña se almacena con hash irreversible vía BCryptPasswordEncoder.

    3. ProposalDocument¶

    Historial de versiones de la propuesta comercial y pedagógica enviada a la empresa (§4.1.3). - Versionado automático: Cada revisión o contrapropuesta genera un nuevo registro con número de versión incremental (version). - Archivo binario (pdf_blob): Contiene el PDF compilado por ProposalPdfBuilder, permitiendo a la empresa y a la institución descargar cualquier versión histórica.

    Estados y Etapas (CourseStage y CourseStatus)¶

    La interfaz y los DTOs calculan la etapa visual (CourseStage) dinámicamente: - Etapas activas (en curso): EN_EVALUACION, PROPUESTA_ENVIADA, EN_PREPARACION, CONFIRMADO_PENDIENTE_INICIO, EN_DESARROLLO, EN_ELABORACION_INFORME. - Etapas cerradas/terminales: Mapeadas desde CourseStatus (FINALIZADO, CANCELADO, RECHAZADO, NO_VIABLE, SIN_RESPUESTA).
